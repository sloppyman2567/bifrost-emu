# bifrost-emu

AArch64 Linux user-mode emulator for x86_64 Linux hosts: FrostJIT, reference
interpreter, Linux syscalls/VFS, dynamic linking, Android runtime and host
graphics/audio adapters.

## Where things are

- [Docs/ARCHITECTURE.md](Docs/ARCHITECTURE.md): source layout, subsystem ownership and entry points. Start here.
- [Docs/JIT.md](Docs/JIT.md): **read before any JIT, shared decoder or IR work.**
- [Docs/TESTS.md](Docs/TESTS.md), [Docs/ROOTFS.md](Docs/ROOTFS.md), `Docs/Android/`: tests, guest rootfs, Android runtime.
- `Docs/archive/`: dated history, not required reading.
- `Source/` (headers beside sources), `Include/Bifrost/` (public headers), `Include/Generated/` (generated tables),
  `Guest/` (guest-side code), `Scripts/` and `Tools/` (setup, launcher, site).
- The version lives in `Include/Bifrost/Version.hpp`; keep README, Makefile, sample config, rootfs `os-release` and
  `Docs/CHANGELOG.md` in step with it.

## Working rules

- Start from the concrete failure, trace the first wrong value and compare with a trusted reference. Prefer primary
  sources. Say which claims were checked against a source and which were only observed in tests.
- Keep correctness first: guest/host address boundaries, mapping and signal semantics, register widths and precise
  fault state. Never tailor runtime behaviour to one host, kernel or benchmark.
- Preserve uncommitted work, keep changes scoped and stay on the current branch. Commit related code and docs only;
  never push without explicit approval.
- Update the docs after the change. Guides describe how things work now; history goes to `Docs/archive/`.
- Keep throwaway probes and logs outside the repository. Diagnostic switches belong in
  `Source/System/Core/DebugFlags.hpp`, not in repeated `getenv` calls.
- Name files after what they implement, never "misc", "common" or "core".
- A new script with a shebang needs `git update-index --chmod=+x PATH` (`core.fileMode` is false here).
- The project site is generated by `Tools/Site/build-site.py`: edit the README, `compatibility.json` and
  `Tools/Site/*.html`, never the generated pages. Record a compatibility change in both the README table and
  `compatibility.json`, or the site build fails.
- Setup scripts find host tools through `Scripts/Setup/find-host-tools.sh` and download through
  `download_progress.fetch`. The setup step list in `Scripts/Android/android_provisioning.py` stays in step with
  the Makefile's `android-provision` and `install-asgard.py`.
- In the desktop library an uncaught exception in a Qt slot aborts the process: catch it in the gamepad path, and
  end `QProcess` children before Qt destroys them.

## Build and validation

```sh
make -j8 USE_SDL2=1 USE_THUNK_GL=1 all lib
make setup-tests
make generated-check
bash Scripts/Testing/run_tests.sh --strict
bash Scripts/Testing/run_tests.sh --no-jit --strict
make verify
```

Run emulator and test commands with GPU access. Headless builds (`USE_SDL2=0 USE_THUNK_GL=0`) have separate object
trees and are validated separately. Run the focused regressions for the changed contract, and report missing
optional fixtures and remaining limitations: a passing build or smoke launch does not establish game playability.
