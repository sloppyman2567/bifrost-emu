# Host graphics and display

- Emit trampolines through `write_thunk_trampoline()`: load the symbol ID into
  x9, dispatch via SVC, then return. Hand-encoding MOVZ x0 routes the wrong call.
- Guest pointers/handles must round-trip through guest memory. Bounce ranges
  that are not accessible as one host range and preserve bounded writeback.
  Prefer DisplayProxy for THUNK_PROXY handles; raw host Display pointers cannot
  be returned as guest pointers. Host fallback remains the headless path.
- `Tools/CodeGen/thunk_dp.txt` is the signature/policy source of truth for GL,
  GLES, EGL, SDL and display APIs. Regenerate with `make opgen-thunk`; use the
  Wayland/Vulkan generators for their tables. Keep explicit special policies
  outside generic autogenerated coverage blocks.
- Guest `*GetProcAddress` returns NULL for names without a row, and guests
  (Chromium, Unity) call advertised entry points unchecked. `glcoverage.py`
  generates rows for every registry extension command it can thunk (aliases and
  promoted commands copy the core row). ES extensions with an unthunkable command
  go to `Include/Generated/GLExtensions.hpp`, and `ExtensionFilter.cpp` removes
  them from the guest's `glGetString`, `glGetStringi` and `GL_NUM_EXTENSIONS`.
  Desktop GL keeps the host list. Regenerate with `glcoverage.py`, then
  `make opgen-thunk`; host symbols fall back from `dlsym` to `eglGetProcAddress`. `dlsym(RTLD_DEFAULT)` finds GL only because
  `register_known_symbols_` loads libGL `RTLD_GLOBAL`: nothing names GL at link time, so a toolchain that defaults to
  `--as-needed` (Ubuntu's) drops `-lGL`, and raw lookups then miss (`glMapBuffer` returned NULL).
- `vkcoverage.py` generates the core-Vulkan rows `thunk_dp.txt` is missing from
  `vk.xml`: `VK_CMD_DEEP`/`_OUT` when `vkmarshalgen.py` has a plan (nested guest
  pointers staged), plain `VULKAN` when every pointer pointee is pointer-free
  (recursively, function pointers and `pNext` included), and `f` args only for
  the mixed shapes `Dispatch.cpp` forwards verbatim. Fixed C array parameters
  (`const float blendConstants[4]`) decay to pointers and must be `p`. Commands
  that need a hand arm (OUT struct writeback, template payloads, uncounted
  `void*`) are printed with the reason; `vkxmlcheck.py` fails a DEEP row whose
  command has no generated plan. Regenerate with `make vkcoverage`, then `make
  vkmarshal opgen-thunk`. The same rule binds hand rows: `vkxmlcheck.py` fails a `VULKAN` row
  whose pointees carry pointers (`vkcoverage.plain_safe`: `pNext`, arrays, function pointers)
  unless `HAND_ARMS` names the arm that marshals it. Such a command gets a plan in
  `vkmarshalgen.py` (`CMD_CREATE_PLANS`, `CMD_STRUCT_IO_PLANS`, or `CMD_NULLIFY_PLANS` for an
  allocator-only destroy) and `VK_CMD_DEEP`/`VK_CMD_DEEP_OUT`. Plain `VULKAN` copies only the top
  struct, so a `pNext` chain reached RADV as a guest pointer (`vkCreateImageView`). The rule covers `-`
  rows as well. Struct descriptors size each pointer member's elements from vk.xml (`vkxml.py`): a
  counted `void*` is a byte buffer and enums/flags use their own size, never a pointer's 8.
- `vkAllocateMemory` stages its `pNext` chain but keeps only structs whose meaning survives the bridge
  (dedicated, allocate flags, priority, capture address); import/export structs carry guest fds or
  pointers and are dropped.
- The Android guest's Vulkan *driver* is `Guest/Android/Adapters/vulkan_hal.c`,
  built as `managed/vulkan.bifrost.so` and installed at
  `/vendor/lib64/hw/vulkan.bifrost.so` with `ro.hardware.vulkan=bifrost`. It is
  a HAL module (`HMI`, `hwvulkan_device_t`) plus ICD entry points, owns no Vulkan
  state, and forwards through `0x100D` to the host loader's thunked symbols; it
  filters the loader-provided `VK_KHR_android_surface` out of
  `vkCreateInstance` because the host Linux loader rejects it. Add a new
  `libvulkan.so` case to the `0x100D` resolver in `Syscalls/HostCalls/Thunks.cpp`
  before relying on it. `vulkan_native_buffer.c` supplies the loader's
  `VK_ANDROID_native_buffer` handshake (`vkAcquireImageANDROID`,
  `vkQueueSignalReleaseImageANDROID`, plus create/destroy device/image and
  device-extension enumeration wrappers): the gralloc allocation is a sealed
  memfd the host driver cannot import, so it copies through a host-visible
  staging buffer (cached memory first: the CPU reads it back every frame)
  inside the loader's acquire/release fences and semaphores.
  `vkCreateImage` strips `VkNativeBufferANDROID`, creates an ordinary host image
  with its own memory and remembers the gralloc layout; destroy the image
  before freeing that memory. Keep the copy serialized (`copy_mutex`). After an image's first release the acquire
  upload is skipped (`host_current`): the host image already holds what the release wrote into the gralloc buffer and
  the compositor only reads it, so an empty submission signals the loader's semaphore and fence. Anything that starts
  writing a swapchain buffer from outside must clear that flag.
- The instance `apiVersion` the guest requested (`VkApplicationInfo.apiVersion`,
  offset 44, read at `vkCreateInstance` before pointer translation) is the version the
  Khronos loader built the device dispatch tables for. A newer core **device** command
  makes the loader tail-jump a null slot and the host dies at `pc=0` (seen with
  `vkGetBufferMemoryRequirements2` on a 1.0 instance and `vkMapMemory2`, 1.4 core, on a
  1.1 one). `Dispatch::dispatch` rejects those calls with `VK_ERROR_FEATURE_NOT_PRESENT`
  using the generated `vk_core_version` table. Instance commands are resolved from the
  ICD regardless of version and are not gated; extension-only commands are absent from
  the table. The most recent `vkCreateInstance` wins, and `test_vulkan` covers both the
  1.4 path and the rejection on a 1.0 instance.
- GL binding state is per context. `GraphicThunkImpl::tracker()` returns the
  calling thread's current EGL context's `GLStateTracker` (switched after a
  successful `eglMakeCurrent`), else the default tracker for SDL/GLFW GL.
  Pointer-vs-buffer-offset decisions, query answers and bind elision must
  use it, never a shared tracker; `gles_contexts` checks this.
- Android `EGL_NATIVE_BUFFER_ANDROID` images (`AndroidBufferImages`) are
  tagged guest handles over a read-only host mapping of the gralloc memfd.
  Each GL context gets its own host texture and EGL image. Refresh with
  `glTexSubImage2D` (glTexImage2D would orphan the image's storage), and
  restore every unpack/texture binding touched so the tracker's view holds.
  RGBA8 buffers upload straight from the mapping (GL_UNPACK_ROW_LENGTH for the
  gralloc stride, reset afterwards); other formats convert into one scratch
  shared by all images, never a copy per image. YUV 4:2:0 converts through
  `Android/Surface/Yuv420.cpp` (shared with SurfaceView, SIMD where the host has it). A texture can only be deleted
  in its own context, so one left by an image destroyed elsewhere waits in
  `stale_textures_` for that context's next bind.
- A native fence is a host `sync_file`: `AndroidNativeFences` publishes it as a guest descriptor and translates a guest
  fd before the driver takes ownership. Never pass a guest fd number to the driver. `gles_native_fence` covers this.
- Graphics symbol ids use two banks (`0x0000` and `0x3000`, 8192 entries);
  every soname registration takes one.
- Preserve stack/FP argument ABI, nested pointer arrays and string returns.
  A `const char* const*` argument is not translated by the generic `p` pointer rule (that only
  turns the array's own address into a host pointer; every entry stays a guest address and the
  driver's `strlen` dies on it). Give the row `SHADER_SOURCE` (glShaderSource), `TF_VARYINGS`
  (glTransformFeedbackVaryings, count in arg 1, array in arg 2, a GLenum in arg 3) or
  `STRING_ARRAY` (array in arg 2, count in arg 1, any other arguments and the return value on
  the generic path: glGetUniformIndices, glCreateShaderProgramv). The array is read through
  guest memory, so a count that outruns it cannot fault the host. `gles_string_arrays` covers
  them; a new function taking an array of strings needs a row with one of these policies.
  `glxmlcheck.py` (part of `make generated-check`) fails any GL/GLES row whose `gl.xml` parameter
  is a pointer-to-pointer but whose policy is `-`; a command that must stay unhandled goes on its
  `NESTED_PENDING` list with a reason and is reported as PENDING (the list is empty now).
- A query that writes a pointer into a guest `void *` (glGetPointerv, glGetBufferPointerv,
  glGetVertexAttribPointerv and their EXT/KHR/OES/NV forms) has policy `POINTER_QUERY`: after the
  host call the dispatcher replaces the driver's value with the one the guest was given, namely the
  map bounce for `GL_BUFFER_MAP_POINTER` (NULL when unmapped), the stored `glDebugMessageCallback`
  function and user parameter (the driver never sees them), and, for a client vertex array, its
  guest address (the host address inside the window that aliases guest memory, less the window
  base; a byte offset into a bound buffer stays). A client array that was bounced rather than
  aliased has no guest address to recover. `gles_pointer_queries` covers it.
- `glCompileShader` has policy `COMPILE_SHADER`. The `SHADER_SOURCE` handler keeps an ES 3.x source
  (`#version 3x0 es`) in `es_shader_sources`, keyed by the calling context's tracker and the shader name, and
  the compile removes it. If the driver rejects the source, `ShaderIndexConversion` wraps the operand of each
  `[E * N + M]` index in `int()` (Mesa refuses SPIRV-Cross's `uint * 1 + 0`; mobile drivers accept it) and the
  shader is compiled once more; if that fails too, the app's own source is put back and compiled, so status,
  log and `glGetShaderSource` are the app's. A shader the driver accepts is never changed. It is the only
  rewrite: other implicit conversions still fail as they did. `gles_uint_index` and `make
  test-shader-index-conversion` cover it.
- The Android `libGLESv2.so` exports exactly the GLES rows, and Bionic binds an app library's imports at `dlopen`,
  so one missing core function fails the whole library (YouTube's `libgoogle3.so`: `glGetUniformBlockIndex`,
  `glTexImage3D`). Every core ES 2.0-3.2 command needs a GLES row: `glxmlcheck.py` fails a missing one (CORE-ES;
  `glReadPixels` is the one exception, appended by `build-android-adapters.py`), and `glcoverage.py` generates
  them, skipping only commands whose pointer has a computed bulk size (a `const GLchar *` with `COMPSIZE()` is a
  string, not a bulk buffer). `Scripts/Android/test_android_adapter_exports.py` checks the built library.
- `GraphicThunk::dispatch`, `DisplayThunk::dispatch` and `AudioThunk::dispatch` mark the symbol
  they run (`thunk_call::Scope`, `Thunks/ThunkCallRecord.hpp`); the host-fault report in
  `FrostJIT/Runtime/FaultHandler.cpp` ends with `thunk=<name>` when the fault happened inside a
  thunk call, i.e. in the driver or libc acting on that call's arguments. The marker holds a name
  pointer only (the handler allocates and locks nothing). A new host-API dispatcher marks its
  calls the same way.
  Guest callback pointers require guest runners, not host function invocation.
  Stage Vulkan storage before taking pointers into it; reallocation invalidates
  those pointers. Preserve deep-marshalling bounds and layout checks.
- Vulkan maps are placed when the device allows it (`DisplayThunk/VulkanPlacedMemory.cpp`):
  `vkCreateDevice` adds `VK_EXT_map_memory_placed` + `VK_KHR_map_memory2` when the host has
  `memoryMapPlaced` and `memoryUnmapReserve` (alignment at most a page; a refused create is
  retried with the app's info), and `vkMapMemory` maps the whole allocation at a fresh guest range
  and returns base + offset. The guest then uses the real memory: no baseline, push or pull. Every
  placed map is unmapped with `VK_MEMORY_UNMAP_RESERVE_BIT_EXT` before its memory is freed or its
  device destroyed, then `Memory::restore_anonymous` puts guest memory back and the range is
  released, so the window never has a hole. The extension is hidden from the guest's list. Anything
  else (no extension, unaligned allocation size, unknown allocation) keeps the bounce below;
  `BIFROST_VK_NO_PLACED=1` forces it. Not handled: a guest munmap/MAP_FIXED over a placed range
  (the driver memory would be reused as plain memory) and a forked child inheriting the mapping.
- ASTC LDR for Vulkan guests on a host without it (`DisplayThunk/VulkanAstc.cpp`, codecs in
  [TextureCodec](TextureCodec/AGENTS.md)): when the host reports no `textureCompressionASTC_LDR` but has
  `textureCompressionBC` and sampleable BC7, the guest is told ASTC works. Hooks are chosen per symbol at registration
  (`SymbolEntry::vk_hook`) and run on the staged arguments: feature and format queries answer for the BC7 equivalent
  (`vkGetPhysicalDeviceFeatures`/`Features2`, `FormatProperties`(2), `ImageFormatProperties`(2)); `vkCreateDevice`
  drops the ASTC feature and enables BC; `vkCreateImage`/`vkCreateImageView` (and a view-format list) use the BC7
  format and the image is recorded; `vkCmdCopyBufferToImage`(2) is redirected to a BC7 scratch buffer (a few 32 MiB
  host-visible blocks per device, one `VkBuffer` each) and the ASTC regions are transcoded at `vkQueueSubmit`(2),
  after `vk_sync_push_all`, from the staging memory's host mapping (the memory is mapped briefly when the guest
  has already unmapped it). Each upload is first copied into a per-thread cached buffer (`copy_from_mapping`, streaming
  loads): staging is usually an uncached host-visible type, and the codec reads every block at least twice, so never
  hand it the mapping itself. Scratch lives while the command buffer's pending list does: it ends at begin, reset,
  free, pool reset or destroy, device destroy; `vkCmdExecuteCommands` adopts a secondary's copies. Regions need
  4-texel alignment (or the mip edge) and are dropped with a once-only note otherwise. Not covered: reading back,
  copying or blitting an ASTC image, ASTC render targets, 3D/HDR ASTC, resubmitting an upload command buffer while the
  first submit still runs, and the GL/GLES path. `BIFROST_VK_NO_ASTC=1` turns it off, `BIFROST_ASTC_THREADS` sets the
  transcoder's threads, `BIFROST_ASTC_CACHE_MB` sizes the cache of finished transcodes (re-uploads skip the encoder)
  and `BIFROST_ASTC_STATS=1` logs volume, time (copy included) and hits. The hand arm for `vkGetPhysicalDevice*Properties2/Features2` takes only the two-argument
  shapes. Covered by `vulkan_astc` (guest, through the thunk) and `test-astc-bc7-transcode` (host).
- GL/GLES and Vulkan mapping APIs return guest bounces, never raw host mapping
  pointers. Preserve mapping lifetime, explicit flush/invalidate, pre-submit
  writeback and post-wait readback. A GL bounce mirrors a real host mapping of
  the same range: move bytes through that host pointer, never glBufferSubData
  or the current binding (immutable storage rejects it), and let the host
  validate access bits, flushes and unmaps. Flush offsets are mapping-relative;
  unmap ends persistent mappings too. `test_sdl_gl_mapbuffer` also runs
  natively as the host reference. Existing coherence behavior is not proof of
  full graphics API conformance; see [the JIT guide](../../../Docs/JIT.md).
- `thunk_dp.txt` ARGS strings carry every parameter, including stack-passed
  ones past the eighth (`glBlitFramebuffer` takes ten): a short string passes
  stack garbage to the host.
- Keep Wayland object/version tracking and callback queues coherent across the
  DisplayProxy/DisplayThunk files. Deliver guest listeners after host dispatch,
  not by re-entering the guest midway through a host callback.
- Window stats (`Display/WindowStats.cpp`, `HostSensors`, `StatsOverlay`) are opt-in and the default costs nothing:
  no sampling or GL queries unless `dbg().window_stats_*` is on. Sensors read only generic `/proc`, hwmon, thermal
  and DRM sysfs, take their roots as arguments so tests use fixture trees, and report `unavailable` rather than
  guess; the GPU device comes from the process's own DRM clients, not a GL context. Session RAM
  (`session_memory`) walks page tables, so it runs on its own signal-blocking thread every 5 seconds and the render
  path only loads the atomic result. The overlay panel
  (`StatsOverlay`) is one ARGB image: an Android window backend shows it as a popup layer, and the X11 desktop
  HUD helper draws the same image from the figures in its `Packet` (`overlay_stats` builds both). Never draw
  statistics through guest GL or Vulkan state. Mode/title/overlay defaults live in `DebugFlags.hpp`.
- Run affected real-GPU GL/EGL/SDL/Vulkan/XWayland probes and the headless header
  check. Rendered smoke frames alone do not validate sustained gameplay.
