# Host graphics and display

- Emit trampolines through `write_thunk_trampoline()`: load the symbol ID into
  x9, dispatch via SVC, then return. Hand-encoding MOVZ x0 routes the wrong call.
- Guest pointers/handles must round-trip through guest memory. Bounce ranges
  that are not accessible as one host range and preserve bounded writeback.
  Prefer DisplayProxy for THUNK_PROXY handles; raw host Display pointers cannot
  be returned as guest pointers. Host fallback remains the headless path.
- `Tools/CodeGen/thunk_dp.txt` is the signature/policy source of truth for GL,
  GLES, EGL, SDL and display APIs. Regenerate with `make opgen-thunk`; use the
  Wayland/Vulkan generators for their tables. Keep explicit special policies
  outside generic autogenerated coverage blocks.
- Guest `*GetProcAddress` returns NULL for names without a row, and guests
  (Chromium, Unity) call advertised entry points unchecked. `glcoverage.py`
  generates rows for every registry extension command it can thunk (aliases and
  promoted commands copy the core row). ES extensions with an unthunkable command
  go to `Include/Generated/GLExtensions.hpp`, and `ExtensionFilter.cpp` removes
  them from the guest's `glGetString`, `glGetStringi` and `GL_NUM_EXTENSIONS`.
  Desktop GL keeps the host list. Regenerate with `glcoverage.py`, then
  `make opgen-thunk`; host symbols fall back from `dlsym` to `eglGetProcAddress`.
- GL binding state is per context. `GraphicThunkImpl::tracker()` returns the
  calling thread's current EGL context's `GLStateTracker` (switched after a
  successful `eglMakeCurrent`), else the default tracker for SDL/GLFW GL.
  Pointer-vs-buffer-offset decisions, query answers and bind elision must
  use it, never a shared tracker; `gles_contexts` checks this.
- Android `EGL_NATIVE_BUFFER_ANDROID` images (`AndroidBufferImages`) are
  tagged guest handles over a read-only host mapping of the gralloc memfd.
  Each GL context gets its own host texture and EGL image. Refresh with
  `glTexSubImage2D` (glTexImage2D would orphan the image's storage), and
  restore every unpack/texture binding touched so the tracker's view holds.
  RGBA8 buffers upload straight from the mapping (GL_UNPACK_ROW_LENGTH for the
  gralloc stride, reset afterwards); other formats convert into one scratch
  shared by all images, never a copy per image. A texture can only be deleted
  in its own context, so one left by an image destroyed elsewhere waits in
  `stale_textures_` for that context's next bind.
- Graphics symbol ids use two banks (`0x0000` and `0x3000`, 8192 entries);
  every soname registration takes one.
- Preserve stack/FP argument ABI, nested pointer arrays and string returns.
  A `const char* const*` argument is not translated by the generic `p` pointer rule (that only
  turns the array's own address into a host pointer; every entry stays a guest address and the
  driver's `strlen` dies on it). Give the row `SHADER_SOURCE` (glShaderSource), `TF_VARYINGS`
  (glTransformFeedbackVaryings, count in arg 1, array in arg 2, a GLenum in arg 3) or
  `STRING_ARRAY` (array in arg 2, count in arg 1, any other arguments and the return value on
  the generic path: glGetUniformIndices, glCreateShaderProgramv). The array is read through
  guest memory, so a count that outruns it cannot fault the host. `gles_string_arrays` covers
  them; a new function taking an array of strings needs a row with one of these policies.
  `glxmlcheck.py` (part of `make generated-check`) fails any GL/GLES row whose `gl.xml` parameter
  is a pointer-to-pointer but whose policy is `-`; a command that must stay unhandled goes on its
  `NESTED_PENDING` list with a reason and is reported as PENDING (the list is empty now).
- A query that writes a pointer into a guest `void *` (glGetPointerv, glGetBufferPointerv,
  glGetVertexAttribPointerv and their EXT/KHR/OES/NV forms) has policy `POINTER_QUERY`: after the
  host call the dispatcher replaces the driver's value with the one the guest was given, namely the
  map bounce for `GL_BUFFER_MAP_POINTER` (NULL when unmapped), the stored `glDebugMessageCallback`
  function and user parameter (the driver never sees them), and, for a client vertex array, its
  guest address (the host address inside the window that aliases guest memory, less the window
  base; a byte offset into a bound buffer stays). A client array that was bounced rather than
  aliased has no guest address to recover. `gles_pointer_queries` covers it.
- `GraphicThunk::dispatch` marks the symbol it runs (`thunk_call::Scope`,
  `Thunks/ThunkCallRecord.hpp`); the host-fault report in `FrostJIT/Runtime/FaultHandler.cpp` ends
  with `thunk=<name>` when the fault happened inside a graphics thunk call, i.e. in the driver or
  libc acting on that call's arguments. The marker holds a name pointer only (the handler
  allocates and locks nothing); AudioThunk and DisplayThunk calls are not marked.
  Guest callback pointers require guest runners, not host function invocation.
  Stage Vulkan storage before taking pointers into it; reallocation invalidates
  those pointers. Preserve deep-marshalling bounds and layout checks.
- GL/GLES and Vulkan mapping APIs return guest bounces, never raw host mapping
  pointers. Preserve mapping lifetime, explicit flush/invalidate, pre-submit
  writeback and post-wait readback. A GL bounce mirrors a real host mapping of
  the same range: move bytes through that host pointer, never glBufferSubData
  or the current binding (immutable storage rejects it), and let the host
  validate access bits, flushes and unmaps. Flush offsets are mapping-relative;
  unmap ends persistent mappings too. `test_sdl_gl_mapbuffer` also runs
  natively as the host reference. Existing coherence behavior is not proof of
  full graphics API conformance; see [the JIT guide](../../../Docs/JIT.md).
- `thunk_dp.txt` ARGS strings carry every parameter, including stack-passed
  ones past the eighth (`glBlitFramebuffer` takes ten): a short string passes
  stack garbage to the host.
- Keep Wayland object/version tracking and callback queues coherent across the
  DisplayProxy/DisplayThunk files. Deliver guest listeners after host dispatch,
  not by re-entering the guest midway through a host callback.
- Window stats (`Display/WindowStats.cpp`, `HostSensors`, `StatsOverlay`) are opt-in and the default costs nothing:
  no sampling or GL queries unless `dbg().window_stats_*` is on. Sensors read only generic `/proc`, hwmon, thermal
  and DRM sysfs, take their roots as arguments so tests use fixture trees, and report `unavailable` rather than
  guess; the GPU device comes from the process's own DRM clients, not a GL context. The in-window overlay is an
  ARGB image for a window backend's popup layer (Android only); never draw
  statistics through guest GL or Vulkan state. Mode/title/overlay defaults live in `DebugFlags.hpp`.
- Run affected real-GPU GL/EGL/SDL/Vulkan/XWayland probes and the headless header
  check. Rendered smoke frames alone do not validate sustained gameplay.
